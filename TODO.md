- [ ] **WITH / COVAR edges never carry estimates.** `attachEstimates` in `app/src/model/graph.ts` attaches only codes 1 and 11 to edges. Code-2 and code-12 rows are matched but not stored, though the same function builds COVAR edges from code-2 rows, so every covariance edge shows no number and indeterminate significance. Evidence that code 2 is the unstandardized covariance and code 12 its STDYX form (a correlation): code 12 equals code 2 divided by the square root of the two code-4 residual variances, which held for every non-sentinel pair checked (in `dgm/syn_sem.dgm`: `2 1 c4 b4 0.123`, residual variances 0.433 and 0.441, so 0.123 / sqrt(0.433 x 0.441) = 0.281 against `12 1 c4 b4 0.282`), and the Mplus User's Guide v8 (ch. 18) says residual covariances are standardized by residual variances. Mplus does not publicly document the `.dgm` codes. The codes fit a scheme: last digit = parameter type (1 loading or regression, 2 covariance, 4 residual variance, 5 latent variance); tens digit = estimate type (0 unstandardized, 1 STDYX, 2 STDY, 3 STD). 2x codes appear in output run with `OUTPUT: STANDARDIZED` (all three standardizations); whether `OUTPUT: STDYX` alone omits them is not checked. Decision: confirm. Proposed: attach 2 to `unstd` and 12 to `stdyx` on WITH/COVAR edges, by analogy with 1/11. Decided (Amelia, 2026-10-30, after a mockup on `syn_sem`: "yes have the estimates on the covariances but allow user to hide them"): attach them as proposed and label covariance edges like other edges (with significance styling and, once built, the SE); shown by default, with a global toggle to hide covariance labels. Whether to also hide them per edge is not decided. Build with the SE/CI labels below, since both change edge labels.
